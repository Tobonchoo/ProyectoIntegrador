¿Cuál es la Idea de Trabajo Principal?

Formalización y resolución de la asimetría informativa en el comercio gastronómico metropolitano.

🎯

Propósito Central de SLUSH

Consolidar un ecosistema digital especializado que centralice la oferta comercial de puntos de venta de granizados artesanales y de autor en los seis municipios neurálgicos del Valle de Aburrá. A diferencia de los mapas multipropósito convencionales, SLUSH resuelve el vacío de información estructurando los catálogos en función de bases de elaboración (agua frutal, mezclas lácteas cremosas, escarchados michelados o frappés con licor) y relacionándolos con afluencia y precios por onzas.

  • Democratización del posicionamiento local sin comisiones extractivas.
  • Transparencia en tiempos de espera mediante categorización de afluencia.
⚖️

Doble Enfoque de Experiencia de Usuario

La plataforma desacopla operativamente la vista del consumidor frente a la del comerciante. El cliente accede a un mapa interactivo con vectorización de rutas inmediatas y auditoría de opiniones. Por su parte, los comerciantes disponen de una vitrina parametrizable para ajustar la disponibilidad de inventario, controlar los precios de adiciones en tiempo real y reportar picos de demanda estacional o climática.

  • Consumidor: Geonavegación, filtros de base y verificación comunitaria.
  • Comerciante: Panel de gestión de catálogo, aforo y analítica territorial.

¿Cuáles Serán Nuestras Reglas de Negocio?

Salvaguardas formales para asegurar la integridad operativa, seguridad y consistencia transaccional.

Código Regla de Negocio Descripción Operativa Mecanismo de Control Técnico
RN-01 Control de Acceso Basado en Roles (RBAC) La consulta cartográfica es pública. La calificación exige rol CLIENTE verificado. La edición de catálogo y local demanda rol COMERCIANTE validado. Llaves Foráneas & JWT
RN-02 Unicidad de Reseña por Ventana de 24h Un usuario solo puede calificar un mismo punto de venta una vez cada 24 horas, anulando ataques de descrédito o spam. Stored Procedure T-SQL
RN-03 Dominio de Calificación Acotado El puntaje de evaluación debe oscilar indefectiblemente entre 1.0 y 5.0 puntos decimales. CHECK Constraint
RN-04 Geolocalización en Polígono Metropolitano Las coordenadas deben inscribirse obligatoriamente dentro de las fronteras físicas de los seis municipios del Valle de Aburrá. CHECK Geográfico
RN-05 Precios No Negativos y Tamaños Reales El precio unitario no puede ser inferior a $0 COP y el volumen debe ser mayor a 0 onzas. Niveles: Baja, Media, Alta o Saturado. CHECK Dominio
RN-06 Restricción Multimedia de Evidencia Archivos fotográficos con peso máximo de 5120 KB (5 MB) y extensiones MIME autorizadas (.webp, .jpg, .png). CHECK Peso & Payload
Temas N°3 & N°4

Modelo Entidad/Relación y Modelo Relacional

Estructuración conceptual y formalización matemática de dependencias entre entidades.

MUNICIPIOS & LOCALES (1:N)

Un municipio alberga de 1 a N locales de granizados. Un local pertenece estrictamente a un único municipio del Valle de Aburrá.

MUNICIPIOS (id_municipio [PK], ...)
LOCALES (id_local [PK], id_municipio [FK], ...)

LOCALES & PRODUCTOS (1:N)

Cada local ofrece un catálogo de 1 a N granizados. Cada producto se vincula de manera exclusiva a una tienda específica.

PRODUCTOS (id_producto [PK], id_local [FK], id_categoria [FK], ...)

RESENAS & MULTIMEDIA (1:N)

Un usuario autenticado emite calificaciones sobre un local. Cada reseña puede asociar de 0 a N imágenes de evidencia fotográfica.

RESENAS (id_resena [PK], id_local [FK], id_usuario [FK], ...)
MULTIMEDIA_RESENA (id_multimedia [PK], id_resena [FK], ...)

Tema N°5

Proceso Metodológico de Normalización (1FN a 3FN)

Eliminación de redundancias, supresión de dependencias transitivas y garantía de atomicidad.

Fase de Normalización Estado Inicial (No Normalizado) Tratamiento Aplicado en SLUSH Resultado en Esquema Físico
Primera Forma Normal (1FN) Campos con listas de sabores separados por comas o números de teléfono múltiples en una sola columna. Descomposición atómica de atributos. Creación de una columna por dato elemental y definición de llaves primarias subrogadas IDENTITY(1,1). Tuplas atómicas independientes en PRODUCTOS y LOCALES.
Segunda Forma Normal (2FN) Existencia de dependencias funcionales parciales respecto a claves primarias compuestas hipotéticas. Aislamiento de entidades independientes. La descripción de una base de granizado no depende del local sino de una entidad propia. Creación de la tabla CATEGORIAS vinculada mediante clave foránea id_categoria.
Tercera Forma Normal (3FN) Dependencias transitivas donde atributos no clave determinan a otros atributos no clave (ej. guardar el código DANE o departamento dentro de LOCALES). Supresión de dependencias indirectas. La dirección física únicamente mantiene el puntero foráneo hacia MUNICIPIOS. Cero anomalías de modificación: actualizar un nombre municipal ocurre en un único registro centralizado.

2. Disparador (Trigger): Recálculo Atómico de Calificación 
-- ============================================================================
-- DISPARADOR: TRG_Actualizar_Calificacion_Local
-- ASEGURA RESPUESTAS O(1) EN LECTURAS DEL MAPA RECALCULANDO EL PROMEDIO TRAS
-- CUALQUIER ALTERACIÓN ATÓMICA EN LA TABLA RESENAS.
-- ============================================================================
CREATE TRIGGER TRG_Actualizar_Calificacion_Local
ON RESENAS
AFTER INSERT, UPDATE, DELETE
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @LocalesAfectados TABLE (id_local INT);

    -- Capturar identificadores afectados en tablas virtuales inserted y deleted
    INSERT INTO @LocalesAfectados
    SELECT DISTINCT id_local FROM inserted
    UNION
    SELECT DISTINCT id_local FROM deleted;

    -- Actualización directa del campo materializado en la entidad LOCALES
    UPDATE L
    SET L.calificacion_promedio = ISNULL(Sub.Promedio, 0.00)
    FROM LOCALES L
    INNER JOIN @LocalesAfectados A ON L.id_local = A.id_local
    OUTER APPLY (
        SELECT CAST(AVG(R.puntuacion) AS DECIMAL(3,2)) AS Promedio
        FROM RESENAS R
        WHERE R.id_local = L.id_local
    ) Sub;
END;
GO
3. Procedimiento Almacenado: Registro Seguro y Validación RN-02 
-- ============================================================================
-- STORED PROCEDURE: USP_RegistrarResena
-- ENCAPSULA LA VALIDACIÓN DE REGLA RN-02 (VENTANA 24 HORAS) DENTRO DE UNA
-- TRANSACCIÓN EXPLÍCITA BAJO PROPIEDADES ACID.
-- ============================================================================
CREATE OR ALTER PROCEDURE USP_RegistrarResena
    @id_local INT,
    @id_usuario INT,
    @puntuacion DECIMAL(2,1),
    @comentario NVARCHAR(1000),
    @origen_plataforma VARCHAR(30) = 'SLUSH_Direct',
    @ResultadoMensaje VARCHAR(250) OUTPUT,
    @CodigoEstado INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    BEGIN TRY
        BEGIN TRANSACTION;

        -- Comprobación de regla de negocio RN-02
        IF EXISTS (
            SELECT 1 FROM RESENAS 
            WHERE id_local = @id_local 
              AND id_usuario = @id_usuario 
              AND fecha_registro >= DATEADD(HOUR, -24, SYSDATETIME())
        )
        BEGIN
            SET @CodigoEstado = 400;
            SET @ResultadoMensaje = 'Violación RN-02: Ya has calificado este punto de venta en las últimas 24 horas.';
            ROLLBACK TRANSACTION;
            RETURN;
        END

        -- Inserción de la calificación verificada
        INSERT INTO RESENAS (id_local, id_usuario, puntuacion, comentario, origen_plataforma)
        VALUES (@id_local, @id_usuario, @puntuacion, @comentario, @origen_plataforma);

        COMMIT TRANSACTION;
        SET @CodigoEstado = 200;
        SET @ResultadoMensaje = 'Reseña procesada correctamente. El disparador DML actualizó el promedio.';
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0
            ROLLBACK TRANSACTION;

        SET @CodigoEstado = 500;
        SET @ResultadoMensaje = 'Error de concurrencia o integridad: ' + ERROR_MESSAGE();
    END CATCH
END;
GO

Orquestación del Cliente (HTML5, Leaflet y Lógica ES6+)

Estructura de la aplicación interactiva para visualización espacial, rutas y captura comunitaria.

Decisiones de Arquitectura Web

  • Vanilla JavaScript (ES6+): Cero sobrecarga de Virtual DOM para garantizar navegación fluida en dispositivos móviles en exteriores.
  • Leaflet + CartoDB DarkMatter: Carga asíncrona de teselas cartográficas oscuras con bajo consumo de memoria RAM.
  • Variables Nativas CSS3: Modulación estética centralizada en estilos.css, facilitando temas y adaptabilidad visual.
